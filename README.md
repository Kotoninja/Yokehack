# Yokehack: прогноз отгрузок со складов

Прогноз `target_1h` (объём товаров, отгруженных по маршруту за последний час) для 1000 маршрутов
на 8 точек вперёд с шагом 30 минут: 01.11.2025, 11:00–14:30. Последняя известная точка — 10:30.

**Метрика** (меньше — лучше), считается по всем точкам посылки сразу:

```
score = Σ|ŷ − y| / Σy  +  |Σŷ / Σy − 1|        # WAPE + |Relative Bias|
```

**Посылка:** CSV `id,y_pred`, по одной строке на каждый `id` из `Data/test_solo_track.parquet` (8000 строк).

## Данные

| Колонка | Смысл |
|---|---|
| `route_id` | маршрут (0–999) |
| `timestamp` | шаг 30 мин, 28.07.2025 00:00 – 01.11.2025 10:30, сетка полная |
| `status_1..3` | товары маршрута, прошедшие этапы обработки на текущем складе за 30 мин |
| `status_4..6` | товары, идущие на текущий склад, прошедшие этапы на предыдущем складе за 30 мин |
| `target_1h` | отгружено по маршруту за последний час (окна соседних точек перекрываются) |

Внешние данные запрещены. `Data/` в репозиторий не входит, положите туда `train_solo_track.parquet` и `test_solo_track.parquet`.

## Подход

```
parquet ──► Panel: матрицы [маршрут × время] (y, 6 статусов)
              │
              ▼
        FeatureBuilder: строка = (маршрут, якорь a, горизонт k=1..8)
              │   все признаки только из индексов ≤ a
              ▼
        LightGBM: цель y[a+k] / scale, вес = scale  (L1 ⇒ оптимизирует WAPE)
              │
              ▼
        прогноз × scale  ──►  масштабирование общей суммы  ──►  CSV
```

- **Панель.** Ряды полные и синхронные, поэтому окна и лаги считаются срезами numpy и кумулятивными суммами. Это быстро и без группировок pandas.
- **Якоря.** Обучаемся на ситуациях, повторяющих тест: последняя известная точка в 10:30 ± `slot_radius` получасов, по всем дням с историей не меньше 28 дней.
- **Нормировка.** `scale` — средний `target_1h` маршрута за 7 дней. Одна глобальная модель работает с маршрутами разного масштаба. При L1 с весом `scale` взвешенная ошибка совпадает с WAPE.
- **Признаки v1:** уровни за 1ч–28д, последние значения, сезонные лаги (вчера, неделя назад, среднее за 7 дней и 4 недели в тот же слот), профиль маршрута по слоту, уровни и отношения статусов, общий уровень сети, `k`, слот, день недели.
- **Признаки v2** (`--v2`): темп сегодняшнего дня относительно прошлых дней, приросты статусов за 1ч и 1д, «уровень сегодня × сезонная форма», `route_id` как категория (переобучается, отключается через `--no-route-cat`).
- **Калибровка уровня.** Модель с L1 систематически недооценивает сумму (распределение скошено), а |Relative Bias| штрафует это напрямую. Итоговая сумма прогноза задаётся явно через `--target-sum`.

## Валидация

Последние 14 дней train, якорь 10:30 в каждый день (то же окно 11:00–14:30, что в тесте). Обучающие якоря заканчиваются до первого валидационного окна.

Модели сравниваются по `sum_matched`: скор после приведения суммы прогноза за каждый день к факту. Общий уровень калибруется отдельно, а модель отвечает за распределение объёма по маршрутам и часам.

## Результаты

| Вариант | Валидация (raw) | Лидерборд |
|---|---|---|
| Сезонное среднее 7 дней | 0.362 | — |
| LGBM v1, якорь 10:30, ×1.03 | 0.351 (raw) | 0.347 |
| LGBM v1, якоря 8:30–12:30, ×1.03 → сумма 2.194 млрд | 0.349 (raw), 0.321 (×1.03) | 0.341 |
| то же, сумма 2.21 млрд | | 0.335 |
| то же, сумма 2.25 млрд | | 0.338 |
| **то же, сумма 2.23 млрд** | | **0.328** |

Оптимум общей суммы по лидерборду ~2.23 млрд (оценён по трём посылкам выше и подтверждён четвёртой).

Сравнение вариантов (якоря 9:30–11:30, lr 0.1):

| Вариант | raw | sum_matched |
|---|---|---|
| v1, L1 | 0.3527 | 0.3185 |
| v1, L2 | 0.3224 | 0.3197 |
| v2, L1, с `route_cat` | 0.3524 | 0.3218 (переобучение на маршрут) |
| v2, L1 | 0.3503 | 0.3190 |
| v2, L2 | 0.3217 | 0.3192 |
| v2, Huber | 0.3378 | 0.3185 |
| ансамбль v1 L1 + v2 Huber + v2 L2 | 0.3383 | 0.3180 |

Признаки v2 и ансамбль дают выигрыш меньше 0.001: при правильно выставленной сумме модели упираются в шум ряда. L2 почти не смещён по сумме (raw близок к sum_matched), а L1 занижает её на ~3%.

## Структура

```
forecast/
  features.py       Panel, FeatureBuilder (v1/v2), метрика score
  validate.py       одиночный прогон валидации, бейзлайны, скан множителя
  experiment.py     кэш признаков + варианты моделей → runs/val_<name>.parquet, runs/results.jsonl
  blend.py          подбор весов ансамбля по валидационным прогнозам
  train_predict.py  обучение на всём train → runs/test_<name>.parquet → CSV посылки
SimpleBaseline/     бейзлайн организаторов (Ridge) и пример посылки
runs/               кэши, логи, промежуточные прогнозы (не в git)
```

## Запуск

Нужен Python 3.12 и [uv](https://docs.astral.sh/uv/). На macOS для LightGBM нужен `brew install libomp`.

```bash
uv sync
```

```bash
uv run python -m forecast.experiment v1_l1 v2_l1 v2_l2 v2_huber
```

```bash
uv run python -m forecast.blend v2_l1 v2_l2 v2_huber
```

```bash
uv run python -m forecast.train_predict --name v2_l1 --v2 --rounds 900 --target-sum 2.23e9 --out test.csv
```

```bash
uv run python -m forecast.train_predict --blend v2_l1:0.6 v2_l2:0.4 --target-sum 2.23e9 --out test.csv
```

Полное обучение на якорях 8:30–12:30 (~4.9 млн строк) занимает 15–50 минут на ноутбуке, в зависимости от `lr` и числа итераций.
